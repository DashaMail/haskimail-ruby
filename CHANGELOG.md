# Изменения

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [1.0.0] — 2026-11-12

Первый публичный выпуск.

### Добавлено

- `AccountClient#servers.issue_token(server_id, name:)` — выпуск дополнительного серверного
  API-ключа (`POST /servers/{id}/tokens/new`); открытое значение ключа возвращается один раз.
- Все 61 метод справочника API Haskimail: отправка (одиночная, пакетная, по шаблону), шаблоны,
  сообщения, открытия и клики, входящие письма, возвраты, серверы, каналы, домены, статистика,
  вебхуки, правила для входящих, стоп-листы.
- `ServerClient` (ключ сервера) и `AccountClient` (ключ аккаунта: серверы, домены, перенос
  шаблонов и данные всех серверов аккаунта).
- Разбор и проверка подписи вебхуков: доставка, отправка в песочнице, возврат, открытие, клик,
  жалоба, изменение подписки; разбор входящих писем с декодированием вложений.
- Повторы с экспоненциальной задержкой и учётом `Retry-After` без риска повторной отправки письма.
- Проверка документированных лимитов до отправки: получатели, длина полей, размеры тел и вложений,
  запрещённые типы файлов, защита от подмены заголовков письма.
- Ленивая пагинация, неизменяемые потокобезопасные клиенты и ответы, типизированные ошибки и все
  коды ошибок API в `Haskimail::ErrorCodes`, тестовые адреса `Haskimail::TestAddresses`.
- RBS-сигнатуры публичного API и внутренностей; код проверяется Steep. Документация YARD — 100%.
- `Haskimail.parse_time` разбирает все форматы дат API: `YYYY-MM-DD HH:MM:SS` (МСК), ISO 8601 и RFC 2822
  (`Date` входящего письма); нулевая дата `0000-00-00 00:00:00` даёт `nil`.
- Фильтр `status:` входящих писем принимает любой регистр (API сам отдаёт `"Failed"`, `"Blocked"`).
- Нет runtime-зависимостей; Ruby 3.1 – 4.0, json 2.x и 3.x.
- `BatchResult` — значение: `==`, `to_json`/`as_json`, `empty?`. `ApiObject` переживает `Marshal`
  (например, `Rails.cache`) и остаётся неизменяемым.

### Безопасность

- Только HTTPS с TLS 1.2+ и проверкой сертификата; `ca_file` добавляет CA к системным, а не
  заменяет их.
- Ключи и пароль прокси не попадают в `inspect`, логи, YAML и JSON; клиенты, запросы и настройки
  нельзя сериализовать через `Marshal`.
- Прокси из окружения (`https_proxy`, `HTTPS_PROXY`, `http_proxy`, `no_proxy` с `*` и `*.domain`)
  проверяется так же, как явный: только `http://`; `HTTP_PROXY` игнорируется (httpoxy).
- Защита от подстановки заголовков письма при любом написании имён полей (`"subject"`, `:replyTo`),
  в пользовательских заголовках и в `Name`/`ContentType`/`ContentID` вложений.
- Повтор POST только когда запрос точно не ушёл; это определяется по этапу соединения, а не по
  классу ошибки.
- Неопределённый исход отправки — `UnexpectedResponseError`: нет или не число `ErrorCode`, число
  результатов пакета не совпадает с числом писем.
- Ограничение размера ответа API (64 МБ) и тела вебхука (`max_size:`, ошибка
  `WebhookPayloadTooLargeError`), защита от неоднозначных полей в подписанных событиях.
- Все строки запроса приводятся к UTF-8; битые данные отклоняются до отправки.
