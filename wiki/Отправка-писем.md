# Отправка писем

Отправка работает только с ключом сервера (`Haskimail::ServerClient`).

## Одно письмо

```ruby
require "haskimail"

client = Haskimail::ServerClient.new(ENV.fetch("HASKIMAIL_SERVER_TOKEN"))

result = client.emails.deliver(
  from: "Магазин <shop@example.com>",
  to: "ivan@example.com",
  subject: "Ваш заказ №1042 оформлен",
  html_body: "<p>Здравствуйте! Заказ №1042 оформлен.</p>",
  text_body: "Здравствуйте! Заказ №1042 оформлен.",
  tag: "orders",
  metadata: { order_id: "1042" },
  message_stream: "2081"
)

result.message_id        # => "6f1c0b2d9e8a4f7b3c5d2e1a0b9c8d7e"
result.submitted_at      # => "2026-10-07 14:30:12" (московское время)
result.submitted_at_time # => Time
result.error_code        # => 0
```

`deliver` возвращает `Haskimail::SendResult` — неизменяемый объект ответа API (`To`, `SubmittedAt`,
`MessageID`, `ErrorCode`, `Message`) с полями в `snake_case`. Если API отклонил письмо, бросается
исключение (обычно `Haskimail::UnprocessableEntityError`, см. [[Обработка ошибок]]).

Дополнительно у `SendResult` есть:

| Метод | Описание |
|-------|----------|
| `success?` | `true`, если `ErrorCode` равен 0 |
| `message_ids` | Массив `MessageID` (API склеивает их через запятую, по одному на получателя) |
| `submitted_at_time` | `SubmittedAt` как `Time` |

## Параметры письма

Поля передаются ключевыми словами в `snake_case`, SDK сам переводит их в имена API. Можно передать и
Hash с точными именами API: `client.emails.deliver({ "From" => "...", "HtmlBody" => "..." })`.

| Параметр | Поле API | Описание |
|----------|----------|----------|
| `from:` | `From` | Отправитель: `"shop@example.com"` или `"Магазин <shop@example.com>"`. Обязателен |
| `to:` | `To` | Получатели: строка через запятую или массив строк. Обязателен |
| `cc:`, `bcc:` | `Cc`, `Bcc` | Копия и скрытая копия: строка или массив |
| `reply_to:` | `ReplyTo` | Адрес для ответа |
| `subject:` | `Subject` | Тема |
| `html_body:`, `text_body:` | `HtmlBody`, `TextBody` | Тело письма; нужно хотя бы одно непустое |
| `tag:` | `Tag` | Тег для поиска и статистики |
| `metadata:` | `Metadata` | Ваши данные «ключ — значение»; ключи не переименовываются |
| `headers:` | `Headers` | Свои заголовки письма (см. ниже) |
| `attachments:` | `Attachments` | Вложения (см. ниже) |
| `track_opens:` | `TrackOpens` | Отслеживать открытия: `true` / `false` |
| `track_links:` | `TrackLinks` | Отслеживать клики: `"None"`, `"HtmlAndText"`, `"HtmlOnly"`, `"TextOnly"` |
| `message_stream:` | `MessageStream` | ID канала, см. [[Каналы сообщений]] |

Поля со значением `nil` не отправляются. Массив в `to:`, `cc:`, `bcc:` и `reply_to:` склеивается в
строку `"a, b"`. Строки в любой кодировке приводятся к UTF-8; текст, который нельзя привести, —
`Haskimail::ValidationError`.

## Вложения

`Haskimail::Attachment` сам кодирует содержимое в Base64, определяет MIME-тип по расширению и до отправки
отклоняет типы файлов, которые Haskimail не принимает.

```ruby
csv = "id;sum\n1;100\n"

client.emails.deliver(
  from: "billing@example.com",
  to: "client@example.com",
  subject: "Счёт за октябрь",
  html_body: '<p>Счёт во вложении</p><img src="cid:logo">',
  attachments: [
    Haskimail::Attachment.from_file("invoice.pdf"),                         # application/pdf
    Haskimail::Attachment.from_file("invoice.pdf", name: "Счёт-1042.pdf"),  # своё имя файла
    Haskimail::Attachment.new(name: "report.csv", content: csv),            # из строки, text/csv
    Haskimail::Attachment.from_file("logo.png", content_id: "cid:logo")     # встроенная картинка
  ]
)
```

| Метод / атрибут | Описание |
|-----------------|----------|
| `Attachment.from_file(path, name: nil, content_type: nil, content_id: nil)` | Вложение из файла; имя по умолчанию — имя файла |
| `Attachment.new(name:, content:, content_type: nil, content_id: nil)` | Вложение из строки с исходными (не Base64) байтами |
| `name`, `content_type`, `content_id` | Имя, MIME-тип, Content-ID |
| `inline?` | `true`, если задан `content_id` |
| `encoded_size` | Размер после Base64 — именно его Haskimail сравнивает с лимитом |

Неизвестное расширение получает тип `application/octet-stream`. Вложение можно передать и как Hash с
полями API — тогда `content` должен быть уже в Base64:

```ruby
content = [File.binread("invoice.pdf")].pack("m0") # Base64 без переносов строк

client.emails.deliver(
  from: "billing@example.com", to: "client@example.com", subject: "Счёт", text_body: "Счёт во вложении",
  attachments: [{ name: "invoice.pdf", content: content, content_type: "application/pdf" }]
)
```

## Заголовки

```ruby
client.emails.deliver(
  from: "noreply@example.com", to: "user@example.com", subject: "Сброс пароля", text_body: "Ваш код: 123456",
  headers: { "X-Request-Id" => "password-reset-42" }
)

# То же в форме API
client.emails.deliver(
  from: "noreply@example.com", to: "user@example.com", subject: "Сброс пароля", text_body: "Ваш код: 123456",
  headers: [{ name: "X-Request-Id", value: "password-reset-42" }]
)
```

Имена заголовков отправляются как есть и проверяются по RFC 5322; переводы строк и управляющие символы в
значениях запрещены.

## Метаданные

`metadata` — ваши пары «ключ — значение». Они приходят обратно в вебхуках (`event.metadata`,
см. [[Вебхуки]]). Ключи и значения уходят без изменений, в том числе символьные ключи не
переименовываются в CamelCase.

```ruby
client.emails.deliver(
  from: "noreply@example.com", to: "user@example.com", subject: "Добро пожаловать", text_body: "Привет!",
  metadata: { "user_id" => "12345", "campaign" => "onboarding" }
)
```

## Ограничения, которые SDK проверяет до отправки

SDK проверяет [документированные ограничения](https://haskimail.ru/developer/user-guide/send-email-with-api)
до запроса и бросает `Haskimail::ValidationError` — без обращения к сети:

- не больше 50 получателей в `To`, `Cc` и `Bcc` вместе (запятые в кавычках, комментариях `(...)` и `<...>`
  адреса не разделяют);
- `From` — до 255 символов, `Subject` — до 2000, `Tag` — до 1000 (в единицах UTF-16, как считает Haskimail);
- нужен непустой `HtmlBody` или `TextBody`, каждый до 5 МБ; всё письмо вместе с вложениями (после Base64) —
  до 10 МБ;
- вложения без запрещённых расширений: `vbs exe bin bat chm com cpl crt hlp hta inf ins isp jse lnk mdb pcd
  pif reg scr sct shs vbe vba wsf wsh wsl msc msi msp mst` (в том числе `virus.exe. ` и `.exe`);
- для писем по шаблону — ровно одно из `template_id` и `template_alias`;
- в `From`, `To`, `Cc`, `Bcc`, `ReplyTo`, `Subject`, `Tag`, в заголовках, а также в имени, `ContentType` и
  `ContentID` вложений нет переводов строк, управляющих символов и разделителей строк Unicode.

Проверки не обойти другим написанием поля: `"subject"`, `:replyTo` или `"reply_to"` приводятся к
`Subject` / `ReplyTo`, а два написания одного поля в одном письме — тоже `ValidationError`.

```ruby
recipients = Array.new(51) { |i| "user#{i}@example.com" }

begin
  client.emails.deliver(from: "shop@example.com", to: recipients, subject: "Акция", text_body: "...")
rescue Haskimail::ValidationError => e
  puts e.message # => "51 recipients in To, Cc and Bcc; at most 50 are allowed"
end
```

## Проверка без отправки (TEST_TOKEN)

С ключом `Haskimail::TEST_TOKEN` (`"HASKIMAIL_API_TEST"`) API проверяет запрос, но письмо не создаётся и
вебхуки не срабатывают:

```ruby
test_client = Haskimail::ServerClient.new(Haskimail::TEST_TOKEN)
test_client.emails.deliver(from: "shop@example.com", to: "ivan@example.com", subject: "Проверка",
                           text_body: "Тест").error_code # => 0
```

Подробнее о тестовых адресах и песочнице — в [[Тестирование]].
