# Установка и настройка

## Установка

```bash
gem install haskimail
```

Или через Bundler:

```ruby
# Gemfile
gem "haskimail"
```

## Требования

- Ruby 3.1 или новее (CI проверяет 3.1 – 4.0)
- Runtime-зависимостей нет: только стандартная библиотека (`net/http`, `json`, `openssl`)

## Два клиента — два ключа

| Клиент | Ключ | Заголовок | Для чего |
|--------|------|-----------|----------|
| `Haskimail::ServerClient` | ключ сервера | `X-Haskimail-Server-Token` | отправка писем и всё, что относится к одному серверу |
| `Haskimail::AccountClient` | ключ аккаунта | `X-Haskimail-Account-Token` | серверы, домены, перенос шаблонов, данные всех серверов |

```ruby
require "haskimail"

client  = Haskimail::ServerClient.new(ENV.fetch("HASKIMAIL_SERVER_TOKEN"))
account = Haskimail::AccountClient.new(ENV.fetch("HASKIMAIL_ACCOUNT_TOKEN"))
```

Без аргумента клиенты сами берут ключ из окружения: `ServerClient.new` — из `HASKIMAIL_SERVER_TOKEN`,
`AccountClient.new` — из `HASKIMAIL_ACCOUNT_TOKEN`:

```ruby
client  = Haskimail::ServerClient.new
account = Haskimail::AccountClient.new
```

Пустой ключ или ключ с пробелами, переводами строк и не-ASCII символами — `Haskimail::ConfigurationError`
при создании клиента. Ключ не попадает в `inspect`, `to_s` и логи:

```ruby
client = Haskimail::ServerClient.new
client.inspect # => "#<Haskimail::ServerClient base_url=\"https://api.haskimail.ru\" token=[FILTERED]>"
```

Какие ресурсы есть у каждого клиента, см. на страницах разделов `ServerClient API` и `AccountClient API`
на [[Home]]. Отправка писем, входящие письма, правила для входящих и стоп-листы работают только с ключом
сервера.

## Глобальные настройки

```ruby
require "logger"

Haskimail.configure do |config|
  config.open_timeout  = 5                     # секунды на соединение
  config.read_timeout  = 30                    # секунды на чтение ответа
  config.write_timeout = 30                    # секунды на запись запроса
  config.max_retries   = 2                     # 0..10, см. «Повторы и надёжность»
  config.logger        = Logger.new($stdout)   # метод, путь, статус, время — без ключей и адресов
  config.proxy         = "http://user:pass@proxy.local:3128"
  config.ca_file       = "config/corp-ca.pem"  # доп. корневые сертификаты (корпоративный TLS-прокси)
  config.user_agent    = "my-shop/2.1"         # добавляется к User-Agent SDK
end
```

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `base_url` | `"https://api.haskimail.ru"` | Адрес API. Только `https://`, без логина/пароля, query и fragment |
| `open_timeout` | `5` | Таймаут соединения, секунды (положительное число) |
| `read_timeout` | `30` | Таймаут чтения, секунды |
| `write_timeout` | `30` | Таймаут записи, секунды |
| `max_retries` | `2` | Число автоматических повторов, целое от 0 до 10 |
| `logger` | `nil` | Любой объект с методами `debug`, `info`, `warn` (`Logger`, `Rails.logger`) |
| `proxy` | `nil` | Прокси: `nil` — из окружения, строка/URI — явный, `false` — без прокси |
| `ca_file` | `nil` | PEM-файл с CA, которым доверять в дополнение к системным; файл должен существовать |
| `user_agent` | `nil` | Суффикс заголовка User-Agent, только печатные ASCII-символы |

Неверное значение или неизвестный параметр — `Haskimail::ConfigurationError`.

`Haskimail.configure` меняет настройки атомарно: если блок бросил исключение, ничего не меняется.
`Haskimail.configuration` возвращает замороженный объект, `Haskimail.reset_configuration!` восстанавливает
значения по умолчанию (удобно в тестах). Пароль прокси скрыт в `inspect`, `to_h` и YAML, а сохранить
объект настроек через `Marshal` нельзя.

Клиент делает снимок настроек при создании и дальше неизменяем: поздние вызовы `Haskimail.configure`
на уже созданные клиенты не влияют. Один экземпляр клиента можно использовать из многих потоков.

## Настройки для одного клиента

Любой параметр из таблицы можно передать при создании клиента — он перекроет глобальное значение:

```ruby
client = Haskimail::ServerClient.new(ENV.fetch("HASKIMAIL_SERVER_TOKEN"), read_timeout: 10, max_retries: 0)
client.config.read_timeout # => 10
client.config.max_retries  # => 0
```

Ещё два параметра есть только у конструктора: `transport:` (свой HTTP-транспорт) и `sleeper:` (пауза
между повторами). Оба нужны в основном для тестов — см. [[Тестирование]].

## Прокси

Без `config.proxy` SDK берёт прокси из переменных окружения `https_proxy`, `HTTPS_PROXY` или
`http_proxy` (в этом порядке) и, как `URI#find_proxy`, не использует его для loopback-адресов и хостов из
`no_proxy` (имена, суффиксы доменов, диапазоны CIDR). Заглавная `HTTP_PROXY` намеренно игнорируется
(уязвимость httpoxy).

```ruby
# Явный прокси для всех клиентов
Haskimail.configure { |config| config.proxy = "http://user:pass@proxy.local:3128" }

# Прямое соединение для одного клиента: переменные окружения не читаются
direct = Haskimail::ServerClient.new(ENV.fetch("HASKIMAIL_SERVER_TOKEN"), proxy: false)
direct.config.proxy # => false
```

Адрес без схемы (`proxy.local:3128`) понимается как `http://proxy.local:3128`. Схемы `https://` и
`socks5://` дают `ConfigurationError`: Net::HTTP передал бы пароль прокси открытым текстом или не смог бы
им воспользоваться. Трафик до Haskimail при этом всё равно идёт через TLS-туннель (CONNECT).

## TLS

Соединение всегда идёт по TLS 1.2+ с проверкой сертификата и имени хоста; отключить проверку нельзя
намеренно. Если корпоративный прокси подменяет сертификаты, добавьте его CA через `ca_file`.
Редиректы не выполняются.

## Логирование

С `logger` SDK пишет в `debug` каждую попытку запроса (метод, путь, статус, время, номер попытки), а в
`warn` — каждый повтор. Query-строка (в ней бывают адреса получателей), заголовки и тела в лог не
попадают.

```ruby
require "logger"

client = Haskimail::ServerClient.new(ENV.fetch("HASKIMAIL_SERVER_TOKEN"), logger: Logger.new($stderr))
client.messages.list(count: 10)
# D, ... -- : Haskimail GET /messages -> 200 (84 ms, attempt 1)
```
