# Обработка ошибок

## Иерархия исключений

```text
Haskimail::Error                     — базовый класс всех ошибок SDK
├── ConfigurationError               — неверные настройки или ключ (пустой, с пробелами…)
├── ValidationError                  — запрос отклонён до отправки (лимиты, обязательные поля, фильтры)
│   └── WebhookPayloadTooLargeError  — тело вебхука больше max_size
├── SignatureVerificationError       — неверная подпись вебхука
├── ConnectionError                  — сеть: DNS, отказ соединения, обрыв
│   ├── TimeoutError                 — таймаут соединения, чтения или записи
│   └── TlsError                     — ошибка TLS или сертификата
└── ApiError                         — Haskimail ответил ошибкой
    ├── AuthenticationError          — 401: неверный ключ или ключ не того типа
    ├── ForbiddenError               — 403: IP-адрес не в списке разрешённых
    ├── NotFoundError                — 404: неизвестный метод или объект
    ├── PayloadTooLargeError         — 413: пакет больше 50 МБ
    ├── UnprocessableEntityError     — 422: ошибка в данных, смотрите error_code
    ├── RateLimitError               — 429
    ├── ServerError                  — 5xx
    │   └── ServiceUnavailableError  — 503
    └── UnexpectedResponseError      — 2xx с телом, которое SDK не может разобрать
```

`rescue Haskimail::Error` ловит любые сбои запроса, проверки параметров и разбора вебхука. Только вызов
метода Ruby с неверными аргументами (например, без обязательного ключевого слова) даёт обычный
`ArgumentError`.

## Пример

```ruby
require "haskimail"

client = Haskimail::ServerClient.new(ENV.fetch("HASKIMAIL_SERVER_TOKEN"))

begin
  client.emails.deliver(from: "shop@example.com", to: "ivan@example.com", subject: "Заказ", text_body: "Привет!",
                        message_stream: "2081")
rescue Haskimail::ValidationError => e
  puts "Письмо не прошло проверку SDK: #{e.message}"
rescue Haskimail::UnprocessableEntityError => e
  puts "API отклонил письмо: [#{e.error_code}] #{e.error_code_description || e.api_message}"
  puts "Нет такого канала" if e.error_code == Haskimail::ErrorCodes::MESSAGE_STREAM_NOT_FOUND
rescue Haskimail::AuthenticationError
  puts "Проверьте ключ сервера"
rescue Haskimail::ConnectionError => e
  puts "Сеть: #{e.message}, запрос #{e.request_sent? ? 'мог дойти' : 'точно не ушёл'}"
rescue Haskimail::Error => e
  puts "Другая ошибка SDK: #{e.class}: #{e.message}"
end
```

## Атрибуты ApiError

| Атрибут | Описание |
|---------|----------|
| `http_status` | HTTP-код ответа |
| `error_code` | `ErrorCode` из ответа API (`Integer`) или `nil` |
| `api_message` | `Message` из ответа API |
| `error_code_description` | Описание `error_code` на русском из документации или `nil` |
| `response_body` | Тело ответа как строка |
| `response_headers` | Заголовки ответа (имена в нижнем регистре) |

Ответ 2xx с ненулевым `ErrorCode` тоже считается ошибкой и даёт `UnprocessableEntityError`.

API отвечает 404, а не 422, когда объекта нет: шаблон при `get`/`update`/`delete` (1101), канал (1226),
вебхук или сервер (12), домен (510, 512, 516). Класс исключения в этих случаях — `NotFoundError`, но
`error_code` и `api_message` заполнены так же. Если важен именно код, ловите общий
`Haskimail::ApiError` и проверяйте `e.error_code`:

```ruby
begin
  client.templates.get("order-created")
rescue Haskimail::ApiError => e
  raise unless e.error_code == Haskimail::ErrorCodes::TEMPLATE_NOT_FOUND

  puts "Шаблона ещё нет"
end
```

## Коды ошибок: Haskimail::ErrorCodes

Все коды из [справочника ошибок](https://haskimail.ru/developer/api/overview#error-codes) — константы в
`Haskimail::ErrorCodes`, их описания — в `ErrorCodes::DESCRIPTIONS` и `ErrorCodes.describe(code)`:

```ruby
Haskimail::ErrorCodes::TEMPLATE_NOT_FOUND # => 1101
Haskimail::ErrorCodes.describe(1226)      # => "Канал не найден"
```

Самые частые:

| Код | Константа | Описание |
|-----|-----------|----------|
| 10 | `INVALID_API_TOKEN` | Неверный API-ключ |
| 3 | `MISSING_REQUIRED_FIELDS` | Не все обязательные параметры |
| 6 | `INVALID_EMAIL_ADDRESS` | Некорректный email-адрес |
| 36 | `TEMPORARY_SENDING_ERROR` | Временная ошибка отправки, повторите запрос позже |
| 52 | `SENDER_SIGNATURE_NOT_CONFIRMED` | Адрес отправителя не подтвержден |
| 100 | `INTERNAL_ERROR` | Внутренняя ошибка, повторите запрос позже |
| 300 | `INVALID_FIELD_VALUE_OR_BATCH` | Неверное значение поля или неверный пакет писем |
| 701 | `MESSAGE_NOT_FOUND` | Сообщение не найдено |
| 1101 | `TEMPLATE_NOT_FOUND` | Шаблон не найден |
| 1226 | `MESSAGE_STREAM_NOT_FOUND` | Канал не найден |

## Сетевые ошибки и request_sent?

`ConnectionError#request_sent?` говорит, мог ли запрос дойти до Haskimail:

- `false` — сбой при установке соединения (DNS, TCP, CONNECT через прокси, TLS-рукопожатие): запрос точно не
  ушёл, его можно безопасно повторить, даже если это отправка письма;
- `true` — сбой после установки соединения (таймаут чтения, обрыв): письмо могло уйти, проверьте журнал
  сообщений ([[Исходящие сообщения]]) перед повтором.

`original_error` хранит исходное низкоуровневое исключение. SDK сам повторяет запросы там, где это
безопасно, — см. [[Повторы и надёжность]].

## UnexpectedResponseError

Бросается, когда API ответил 2xx, но тело не удаётся интерпретировать: не JSON (например, страница прокси),
`ErrorCode` не число, в ответе на отправку нет `ErrorCode`, или в пакете результатов больше или меньше, чем
писем. SDK не возвращает в таком случае пустые данные. Для отправки это значит: письмо **могло** быть
принято — проверьте журнал сообщений, прежде чем отправлять снова.

```ruby
begin
  client.emails.deliver(from: "shop@example.com", to: "ivan@example.com", subject: "Заказ", text_body: "Привет!")
rescue Haskimail::UnexpectedResponseError => e
  puts "Ответ не распознан (HTTP #{e.http_status}), проверьте журнал сообщений"
end
```

## Ошибки проверки до отправки

`ValidationError` бросается без сетевого запроса: превышены документированные лимиты, нет обязательного
поля, неизвестный фильтр, неверное значение (`color`, `status`, `type`…). Текст сообщения на английском и
указывает поле:

```ruby
begin
  client.bounces.list(type: "Hard")
rescue Haskimail::ValidationError => e
  puts e.message # => "type must be one of: HardBounce, SoftBounce, BlkBounce, SpmBounce, BulkBounce, SpamBlock"
end
```
