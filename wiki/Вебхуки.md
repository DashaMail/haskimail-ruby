# Вебхуки

На этой странице две части: управление вебхуками через API (`client.webhooks`) и приём событий и входящих
писем в вашем приложении (`Haskimail::Webhook`).

## Управление вебхуками

`client.webhooks` (ключ сервера) или `account.webhooks` (ключ аккаунта, все каналы аккаунта).

### Список и получение

```ruby
require "haskimail"

client = Haskimail::ServerClient.new(ENV.fetch("HASKIMAIL_SERVER_TOKEN"))

client.webhooks.list.webhooks.each do |webhook|
  enabled = webhook.triggers.to_h.select { |_name, trigger| trigger["Enabled"] }.keys
  puts "[#{webhook.id}] #{webhook.url} (канал #{webhook.message_stream}): #{enabled.join(', ')}"
end

webhook = client.webhooks.get(905)
webhook.triggers.bounce.enabled # => true
```

### Создать вебхук

```ruby
webhook = client.webhooks.create(
  url: "https://example.com/webhooks/haskimail",
  message_stream: "2081",
  triggers: { delivery: true, bounce: true, spam_complaint: true }
)

webhook.id # => 905
```

Триггеры, которых нет в `triggers:`, выключены. С ключом аккаунта передавайте `message_stream:` явно.
В ответе на создание API отдаёт `MessageStream` числом (`2081`), в остальных ответах — строкой
(`"2081"`); сравнивайте через `to_s`.
URL должен быть `http://` или `https://`; для Basic-авторизации укажите логин и пароль в адресе:
`https://user:pass@example.com/webhooks/haskimail`.

| Ключ в `triggers:` | Триггер API | Событие |
|--------------------|-------------|---------|
| `delivery` | `Delivery` | Письмо доставлено |
| `bounce` | `Bounce` | Возврат |
| `spam_complaint` | `SpamComplaint` | Жалоба на спам |
| `open` | `Open` | Открытие |
| `click` | `Click` | Клик по ссылке |
| `subscription_change` | `SubscriptionChange` | Адрес добавлен в стоп-лист или удалён из него |

Значения — `true` или `false`. Принимается и длинная форма API: `{ "Bounce" => { "Enabled" => true } }`.
Неизвестный триггер или значение не `true`/`false` — `Haskimail::ValidationError`.

### Изменить вебхук

Меняются только переданные поля и триггеры; канал вебхука изменить нельзя.

```ruby
client.webhooks.update(905, triggers: { open: true, click: true })
client.webhooks.update(905, url: "https://example.com/webhooks/haskimail-v2")
```

Вызов без `url:` и `triggers:` — `ValidationError`.

### Удалить вебхук

```ruby
client.webhooks.delete(905).message # => "Webhook 905 removed."
```

## Приём событий

Haskimail отправляет событие POST-запросом с JSON-телом. Проверяйте подпись через `construct_event`:

```ruby
body = File.read("bounce.json") # в Rails — request.raw_post

event = Haskimail::Webhook.construct_event(body, signing_key: ENV.fetch("HASKIMAIL_WEBHOOK_KEY"))

case event.type
when :bounced             then puts "Возврат #{event.recipient}: #{event.bounce_category}" # :hard_bounce
when :complained          then puts "Жалоба от #{event.recipient}"
when :subscription_change then puts "#{event.recipient} в стоп-листе: #{event.suppressed?}"
when :delivered, :opened, :clicked, :sent then puts "#{event.type}: #{event.message_id}"
end
```

Передавайте исходное тело запроса (`request.raw_post`), а не заново сериализованные параметры. Ключ подписи
— из интерфейса Haskimail.

| Метод | Описание |
|-------|----------|
| `Webhook.construct_event(payload, signing_key:, max_size: 1 МБ)` | Разбирает тело и проверяет подпись → `Event` |
| `Webhook.parse_event(payload, max_size: 1 МБ)` | Разбирает **без** проверки подписи — только за другой защитой |
| `Webhook.valid_signature?(event, signing_key:)` | Проверяет подпись разобранного события (Hash или `Event`) → `true`/`false` |
| `Webhook.parse_inbound(payload, max_size: 64 МБ)` | Разбирает входящее письмо → `InboundMessage` (подписи нет) |

Неверная или отсутствующая подпись — `Haskimail::SignatureVerificationError`; тело не JSON-объект, не UTF-8
или с неоднозначными дублями полей — `Haskimail::ValidationError`; тело больше `max_size` —
`Haskimail::WebhookPayloadTooLargeError` (подкласс `ValidationError`). Пустой `signing_key` —
`Haskimail::ConfigurationError`.

### Событие: Haskimail::Webhook::Event

| Метод | Описание |
|-------|----------|
| `type` | `:sent`, `:delivered`, `:bounced`, `:complained`, `:opened`, `:clicked`, `:subscription_change` или `:unknown` |
| `sent?`, `delivered?`, `bounced?`, `complained?`, `opened?`, `clicked?`, `subscription_change?` | Проверка типа |
| `recipient` | Адрес получателя (подписанное поле) |
| `message_id` | ID письма (подписанное поле); `""` для событий без письма |
| `email` | Неподписанная копия `recipient` |
| `tag` | Тег письма (поле `campaign_id`) |
| `metadata` | `metadata` письма как Hash (API присылает JSON-строку `custom_vars`) |
| `server_id`, `stream_id` | ID сервера (`Integer`) и канала (`String`) |
| `occurred_at` | Время события как `Time` (из `event_time_utc`, иначе из `event_time` по Москве) |
| `bounce_category` | `:hard_bounce`, `:soft_bounce`, `:blocked`, `:spam_block` или `nil` |
| `suppressed?` | Для `subscription_change`: адрес добавлен в стоп-лист |
| `idempotency_key` | Ключ для защиты от дублей; у кликов включает ссылку |

Регистр типа события (`complained` / `COMPLAINED`) не важен. Событие `:sent` приходит только с
сервера-песочницы. Остальные поля доступны как у любого ответа API: `event.code`, `event["description"]`,
`event[:url_original]`, `event.to_h`.

Жёсткий возврат и жалоба на спам приходят двумя запросами: `bounced` или `complained`, а следом
`subscriptionchange` для того же письма с `SuppressionReason` `HardBounce` или `SpamComplaint`. У жалобы
`bounce_category` равен `"spm"` (`:spam_block`). Ручное добавление в стоп-лист и удаление из него тоже
дают `subscriptionchange`, но без письма: `message_id` пустой, `custom_vars` нет, а при удалении
`SuppressSending` равен `"false"`.

```ruby
body = File.read("bounce.json")
event = Haskimail::Webhook.construct_event(body, signing_key: ENV.fetch("HASKIMAIL_WEBHOOK_KEY"))

event.metadata        # => {"order_id"=>"1042"}
event.tag             # => "orders"
event.occurred_at     # => 2026-10-07 11:30:15 UTC
event.idempotency_key # => "bounced|a41d7c9e2b6f4e0d8c3b5a1f9e7d2c60|old-address@example.com|2026-10-07 14:30:15|"
```

### Подпись и её ограничения

Подпись Haskimail — `secret = md5(recipient + message_id + ключ_подписи)`. Она подтверждает только эти два
поля: тип события, `SuppressSending`, `custom_vars` и прочее не подписаны. SDK сравнивает подпись в
постоянное время, читает только точные имена подписанных полей, отклоняет неоднозначные дубли полей
(`recipient` и `Recipient`) и ожидает `recipient` вида `local@domain` без пробелов, а `message_id` — из
букв, цифр, `-` и `_`.

Поэтому: используйте HTTPS-URL, держите его в секрете, по возможности добавьте Basic-авторизацию, не
логируйте сырые события целиком. Подробная модель угроз — в
[SECURITY.md](https://github.com/Dashamail/haskimail-ruby/blob/main/SECURITY.md).

### Повторы и дубли

- На событие Haskimail ждёт ответ до 10 секунд, повторяет при ответе 5xx и не повторяет при 4xx.
  Отвечайте быстро, а обработку выносите в фоновую задачу.
- Одно событие может прийти дважды — отсеивайте дубли по `event.idempotency_key`.
- На неверную подпись отвечайте 4xx (`403`): повторять такой запрос Haskimail не будет.

## Входящие письма

Входящие письма приходят на URL, заданный в настройках сервера (`inbound_hook_url`, см. [[Серверы]]).
Они **не подписываются** — защитите URL Basic-авторизацией
(`https://user:pass@your-app.example/hooks/inbound`).

```ruby
body = File.read("inbound.json")
message = Haskimail::Webhook.parse_inbound(body)

message.mailbox_hash        # => "ticket-42" из адреса hash+ticket-42@inbound.haskimail.ru
message.stripped_text_reply # => "Спасибо, всё получил!" — текст ответа без цитаты
message.spam_score          # => 0.3 — из заголовка X-Spam-Score
message.header("Message-ID")
message.attachments.each do |attachment|
  puts "#{attachment.name} (#{attachment.content_type}, #{attachment.size} байт)"
  # attachment.content — уже декодированные байты
end
message.inspect # кратко: MessageID, From, To, Subject и число вложений
```

| Метод | Описание |
|-------|----------|
| `attachments` | Вложения (`InboundAttachment`): `name`, `content_type`, `content_id`, `content`, `size`, `inline?` |
| `header(name)` | Значение заголовка письма (имя без учёта регистра) или `nil` |
| `spam_score` | `X-Spam-Score` как `Float` или `nil` |
| поля API | `from`, `from_name`, `subject`, `text_body`, `mailbox_hash`, `to_h`… |

Имя вложения задаёт отправитель — не используйте его как путь к файлу без очистки.

### Повторы для входящих

Ответ на входящее письмо Haskimail ждёт до 60 секунд и повторяет доставку при **любом** ответе, кроме 2xx и
403 (10 раз, всего около 10,5 часов). Ответ **403 останавливает повторы навсегда**, и письмо получает
статус `Failed`. Поэтому:

- `403` — только на чужие запросы (не Haskimail);
- на `Haskimail::WebhookPayloadTooLargeError` отвечайте `413`, чтобы письмо осталось доступным для
  повтора, и увеличьте `max_size:`;
- письмо с ошибкой можно доставить заново через `client.inbound_messages.retry`
  (см. [[Входящие сообщения]]).

## Пример для Rails

```ruby
# config/routes.rb:
#   post "/webhooks/haskimail", to: "haskimail_webhooks#create"
#   post "/webhooks/haskimail/inbound", to: "haskimail_webhooks#inbound"
class HaskimailWebhooksController < ActionController::API
  include ActionController::HttpAuthentication::Basic::ControllerMethods

  # Входящие письма не подписаны: URL вида https://user:password@your-app.example/webhooks/haskimail/inbound
  http_basic_authenticate_with name: ENV.fetch("HASKIMAIL_INBOUND_USER"),
                               password: ENV.fetch("HASKIMAIL_INBOUND_PASSWORD"),
                               only: :inbound

  # События: ответ до 10 секунд, 5xx повторяется, 4xx — нет
  def create
    event = Haskimail::Webhook.construct_event(request.raw_post,
                                               signing_key: ENV.fetch("HASKIMAIL_WEBHOOK_KEY"))
    HaskimailEventJob.perform_later(event.to_h) # дубли отсеивайте по event.idempotency_key
    head :ok
  rescue Haskimail::SignatureVerificationError, Haskimail::ValidationError
    head :forbidden
  end

  # Входящие письма: 403 останавливает повторы навсегда
  def inbound
    message = Haskimail::Webhook.parse_inbound(request.raw_post)
    HaskimailInboundJob.perform_later(message.to_h)
    head :ok
  rescue Haskimail::WebhookPayloadTooLargeError
    head 413 # письмо останется доступным для повтора
  rescue Haskimail::ValidationError
    head :forbidden # не похоже на запрос Haskimail
  end
end
```

`request.raw_post` в Rack — бинарная строка; SDK сам переводит её в UTF-8. В фоновой задаче событие можно
восстановить: `Haskimail::Webhook::Event.new(payload)`.
